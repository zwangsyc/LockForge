# DECOR — Structural DECOR Implementation



> Quick: the main script is `DECOR_new.py`.

---

## Features
- Parses standard `.bench` combinational netlists.
- Inserts per-bit key gates (XOR/XNOR) in a way that defines a structural key `k*`.
- Samples additional promoted keys and synthesizes `ISCORR` (OR of per-key ANDed XNORs).
- Builds golden (`G_...`) and locked (`L_...`) copies and wires the correction:
  ```
  out = L_out XOR (ISCORR AND (L_out XOR G_out))
  ```
- Emits a DECOR-structured `.bench` file.
- Validates that each promoted key reproduces golden outputs under random input sampling.

---

## Requirements
- Python 3.7+ (pure Python; no external packages required)

## Usage

Basic command:
```bash
python DECOR.py --bench <input.bench> --keys <m> --n_correct <n> --emit <output.bench>
```

Options:
- `--bench` (required) — path to input `.bench` file
- `--keys` (default 16) — number of key bits to insert
- `--n_correct` (default 4) — total number of promoted (correct) keys, including `k*`
- `--seed` (default 42) — RNG seed for reproducibility
- `--emit` — filename to write the DECOR-structured `.bench`
- `--validate_samples` (default 200) — random input vectors per promoted-key for validation

Examples:
```bash
# Create DECOR netlist with 16 keys and 4 promoted keys, emit file
python DECOR_new.py --bench c17.bench --keys 16 --n_correct 4 --emit c17_decor.bench

# Run with larger validation sampling
python DECOR_new.py --bench c880.bench --keys 32 --n_correct 8 --validate_samples 500 --emit c880_decor.bench
```

When run the script prints a concise summary:
- `STRUCTURAL_kstar (first 64):` — the structural key bits derived from inserted XOR/XNOR gates.
- `N_PROMOTED_KEYS:` — number of promoted keys (should match `--n_correct`).
- Per-key validation lines: `KEY: (...) OK: True/False mismatches: X`.
- `ALL_PROMOTED_OK:` — overall validation result.

---

## Validation notes & troubleshooting

- If `ALL_PROMOTED_OK: True` then, under the sampling performed, each promoted key restored the golden outputs.
- If `ALL_PROMOTED_OK: False`, the script prints per-key mismatch counts. Common reasons:
  - Naming mismatch between golden outputs and DECOR outputs (the code uses original output names).
  - Missing `G_`/`L_` fallback nodes (the implementation provides BUFF fallbacks).
  - Constants must be emitted as bare `0`/`1` (not quoted strings) for correct XNOR comparisons.
  - Promoted keys are randomly sampled — if you need guaranteed promoted keys use stricter verification at sampling time (the script validates by sampling input patterns).
- For rigorous equivalence use larger `--validate_samples` or an exhaustive equivalence tool for small circuits.
